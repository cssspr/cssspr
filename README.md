# الموقع الإعلامي الرسمي لمفوضية الأمان الاجتماعي والتكافل وخفض الفقر

موقع إخباري حكومي Full-Stack (Next.js 14 + TypeScript + PostgreSQL + Prisma)، بلوحة تحكم محمية
بنظام أدوار وصلاحيات حقيقي (RBAC)، والجمهور يقرأ ويتصفح دون تسجيل أو حسابات.

## 1. المكدس التقني

- **Next.js 14 (App Router)** + **React 18** + **TypeScript**
- **Tailwind CSS** — نظام ألوان وطباعة عربي مخصص (`tailwind.config.ts`)
- **PostgreSQL** + **Prisma ORM** (`prisma/schema.prisma`)
- **NextAuth (Credentials + TOTP 2FA اختياري)** للمصادقة، مع نظام أدوار وصلاحيات (RBAC) حقيقي
- تخزين سحابي متوافق مع S3 للصور/PDF/الفيديو (`src/lib/uploads.ts`)
- Zod للتحقق من المدخلات، DOMPurify لتنقية HTML، rate-limiter-flexible للحماية من الإغراق

### أنماط جاهزة للتوسّع

`News` و`PressRelease` و`Events`/`Programs`/`Reports`/معرض الصور والفيديو كلها منفَّذة بالكامل
(نموذج بيانات + API + واجهة عرض + لوحة تحكم كاملة بنماذج إضافة/تعديل) — راجع القسم أدناه
"أُنجز بالكامل في هذه الدفعة" لتفاصيل ما اكتمل مؤخراً (الصفحات الثابتة/القيادات/القوائم/التحليلات).
عند الحاجة لإضافة نوع محتوى جديد مستقبلاً بنفس المستوى:
1. انسخ بنية `src/app/api/news/route.ts` و`[id]/route.ts` وبدّل موديل Prisma، مع استبدال مفاتيح
   الصلاحية بما يماثلها (أضِف مفاتيح جديدة في `src/lib/permissions.ts` أولاً، ثم migration مطابقة).
2. انسخ `src/components/admin/NewsForm.tsx` وبدّل الحقول حسب الـ schema، مع الحفاظ على نمط
   `canPublish`/`canDelete` لإخفاء الإجراءات التي لا يملكها المستخدم.
3. أضف صفحة قراءة عامة تقرأ من قاعدة البيانات مباشرة، على غرار `/events`, `/programs`, `/reports`.

### رفع الصور والفيديو وإضافتها بالرابط

عند إضافة صورة أو فيديو أو PDF في أي نموذج بلوحة التحكم تُفتح نافذة بثلاث طرق، **الأولى هي الافتراضية**:

1. **رفع من جهازك** — اضغط أو اسحب الملف؛ تظهر معاينة فورية وشريط تقدّم، ويُتحقق من النوع والحجم قبل الرفع.
2. **من المكتبة** — اختيار ملف مرفوع سابقاً.
3. **رابط مباشر** — لصورة (https) أو فيديو (يوتيوب/فيميو/MP4 مباشر) مع معاينة قبل الإضافة.

الأنواع والحدود: صور JPG/PNG/WebP حتى 15MB (تُصغَّر وتُضغط تلقائياً إلى 2400px)، PDF حتى 25MB، فيديو MP4 حتى 100MB
(تُعدَّل من `MAX_*_BYTES` في `.env`). بدون إعدادات `S3_*` تُحفظ الملفات في `storage/uploads` وتُخدَم من `/uploads`؛
على Vercel أو أي سيرفر بلا قرص دائم استخدم S3. حقل **«مصدر الخبر»** اختياري ويظهر أسفل الخبر (رابط قابل للنقر إن بدأ بـ https://).
بعد تحديث المشروع شغّل `npm run prisma:deploy` لإضافة عمود المصدر (لا يمس البيانات الحالية).

### تسجيل دخول المدير

صفحة `/admin/login` تطلب **رمز الدخول فقط** (بلا اسم مستخدم ولا كلمة مرور). الرمز الافتراضي
`11223344` ويُغيَّر من `ADMIN_LOGIN_CODE` في `.env`. عند صحة الرمز يُسجَّل الدخول بحساب "المدير العام"
(ويُنشأ تلقائياً إن لم يكن موجوداً). بعد تغيير `.env` أو `next.config.js` أعد تشغيل `npm run dev`.

## 4. نظام الأدوار والصلاحيات (RBAC)

النظام يدعم أدواراً متعددة قابلة للتخصيص، وليس مديراً واحداً فقط. كل الصلاحيات (نحو 38 صلاحية)
معرّفة في مكان واحد: **`src/lib/permissions.ts`** — هذا هو المرجع الوحيد عند إضافة صلاحية جديدة.

### الأدوار الافتراضية (تُنشأ تلقائياً عبر migration عند أول تشغيل)

| الدور | المفتاح | الصلاحيات |
|---|---|---|
| مدير عام | `SUPER_ADMIN` | كل الصلاحيات بلا استثناء. محمي: لا يمكن حذفه أو تعديل صلاحياته من الواجهة. |
| مدير محتوى | `CONTENT_MANAGER` | كل صلاحيات المحتوى والوسائط (عرض/إضافة/تعديل/نشر/حذف)، بدون مستخدمين/أدوار/إعدادات/سجل عمليات. |
| محرر | `EDITOR` | عرض/إضافة/تعديل المحتوى فقط (بلا نشر أو حذف) — تُمنح إضافياً من `/admin/roles` عند الحاجة. |
| مُطّلع | `VIEWER` | عرض المحتوى والإحصائيات فقط، دون أي تعديل. |

يمكن إنشاء أدوار جديدة أو تعديل صلاحيات الأدوار الثلاثة غير المحمية من **`/admin/roles`** (تتطلب
صلاحية `roles.manage`، ومتاحة افتراضياً فقط لدور "مدير عام").

### إدارة المستخدمين

من **`/admin/users`** (تتطلب `users.view` للعرض و`users.manage` للتعديل): إنشاء مستخدم جديد،
تغيير دوره، تفعيل/تعطيل حسابه، إعادة تعيين كلمة مروره، أو حذفه.

### حمايات مدمجة على مستوى الـ API (وليس إخفاء أزرار فقط)

- **منع رفع الصلاحيات**: لا يمكن لأي مستخدم منح دور أو مستخدم آخر صلاحية لا يملكها هو نفسه.
- **الحماية من قفل النظام**: لا يمكن تعطيل حسابك الخاص، حذف حسابك الخاص، أو تغيير دورك الخاص.
- **حماية آخر مدير عام**: لا يمكن تعطيل/حذف/تنزيل رتبة آخر مستخدم "مدير عام" نشط في النظام.
- **فورية التطبيق**: أي تغيير في صلاحيات دور أو تعطيل حساب ينعكس فوراً في الطلب التالي للمستخدم
  المتأثر (لا ننتظر انتهاء صلاحية الجلسة بعد 8 ساعات) — راجع `callbacks.session` في `src/lib/auth.ts`.
- **سجل تدقيق كامل**: كل عملية على مستخدم أو دور (إنشاء/تعديل/حذف/إعادة تعيين كلمة مرور) تُسجَّل في
  `audit_logs`، تظهر من `/admin/audit-log`.

### ماذا يحدث لقاعدة بيانات قائمة بالفعل؟

الـ migration الخاصة بـ RBAC (`prisma/migrations/20260909130000_add_rbac`) إضافية بالكامل: أي مستخدم
موجود مسبقاً يُنقل تلقائياً إلى دور "مدير عام" حتى لا يفقد أحد صلاحياته الحالية. لا تُحذف أي بيانات
(أخبار، بيانات صحفية، ملفات، إلخ).

## 5. طريقة إنشاء/تدوير حساب مدير عام

```bash
npm run create-admin
```

يطلب السكربت الاسم والبريد وكلمة مرور قوية (12 حرفاً على الأقل، حرف كبير وصغير ورقم)، ويحفظها
مُشفّرة (bcrypt، 12 rounds)، ويمنح الحساب دائماً دور "مدير عام" (لإنشاء حسابات بأدوار أضيق مثل
مدير محتوى أو محرر، استخدم `/admin/users` بعد تسجيل الدخول). لتفعيل 2FA لهذا الحساب لاحقاً، من
`/admin/settings` (توليد سرّ، عرض QR، تأكيد بالرمز).

### قائمة اختبار يدوي مقترحة لـ RBAC بعد التشغيل

1. سجّل دخولاً بحساب "مدير عام" → تأكد من ظهور كل الروابط في القائمة الجانبية (بما فيها المستخدمون
   والأدوار وسجل العمليات).
2. من `/admin/users`، أنشئ مستخدماً بدور "محرر" → سجّل دخولاً بحسابه في متصفح آخر/نافذة خاصة →
   تأكد من: عدم ظهور روابط المستخدمين/الأدوار/سجل العمليات، إمكانية إنشاء خبر (يُحفظ كمسودة تلقائياً)،
   وعدم ظهور خيار "نشر" ولا زر "حذف".
3. عد لحساب المدير العام وامنح دور "محرر" صلاحية `news.publish` من `/admin/roles` → أعد تحميل صفحة
   المحرر (بلا تسجيل خروج) → يجب أن يظهر خيار النشر فوراً.
4. حاول من حساب المدير العام تعطيل حسابه الخاص، أو حذفه، أو تغيير دوره — يجب أن يُرفض الإجراء بوضوح.
5. إن كان هناك مدير عام واحد فقط في النظام، حاول تعطيله أو حذفه من حساب آخر — يجب أن يُرفض.
6. جرّب الوصول المباشر إلى `/admin/users` من حساب "مُطّلع" — يجب أن تظهر رسالة "لا تملك صلاحية الوصول".

## 7. النشر على السيرفر (إنتاج)

1. **قاعدة البيانات**: وفّر PostgreSQL مُدار (RDS، أو أي مزوّد مشابه) خلف شبكة خاصة، مع نسخ احتياطي تلقائي مفعّل (انظر القسم 7).
2. **التخزين السحابي**: أنشئ Bucket متوافق مع S3 (أو مزوّد محلي) لتخزين الصور/PDF/الفيديو، واربطه عبر `S3_*` في `.env`.
3. **المتغيرات البيئية**: اضبط كل قيم `.env.example` كأسرار في منصة الاستضافة (Vercel/Docker/VM) — **لا تضعها أبداً في الكود أو الـ repo**.
4. **الترحيل**: قبل أول إقلاع، شغّل: `npm run prisma:deploy` (يستخدم `prisma migrate deploy`، آمن للإنتاج ولا يفقد بيانات).
5. **البناء والتشغيل**:
   ```bash
   npm run build
   npm run start   # أو عبر عملية مُدارة (pm2 / systemd / Docker CMD)
   ```
6. **HTTPS**: شغّل الموقع دائماً خلف عاكس عكسي (Nginx/Caddy) أو منصة تدعم TLS تلقائياً؛ رؤوس الأمان (`next.config.js`) تفترض HTTPS (`Strict-Transport-Security`).
7. **CDN**: وجّه الصور والملفات الثابتة عبر CDN أمام bucket التخزين لتحسين زمن الاستجابة.
8. **المراقبة**: راقب جدول `audit_logs` دورياً لرصد أي نشاط إداري غير معتاد.

### مثال Dockerfile (production)

```dockerfile
FROM node:20-alpine AS base
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npx prisma generate && npm run build
EXPOSE 3000
CMD ["npm", "run", "start"]
```

## 8. النسخ الاحتياطي والاستعادة

### قاعدة البيانات (PostgreSQL)

```bash
# نسخ احتياطي يومي (مثال cron)
pg_dump "$DATABASE_URL" -F c -f "backup_$(date +%Y%m%d).dump"

# الاستعادة
pg_restore --clean --if-exists -d "$DATABASE_URL" backup_YYYYMMDD.dump
```

- احتفظ بالنسخ في تخزين منفصل جغرافياً عن قاعدة البيانات الأساسية.
- اختبر الاستعادة دورياً على بيئة staging للتأكد من سلامة النسخ.
- إن كان مزوّد الاستضافة يوفّر نسخاً احتياطياً تلقائياً (Point-in-Time Recovery)، فعّله كطبقة حماية إضافية.

### ملفات الوسائط (S3)

فعّل **Versioning** و**Cross-Region Replication** (أو ما يعادلها) على الـ bucket من إعدادات مزوّد
التخزين، لضمان إمكانية استرجاع أي ملف محذوف أو مُستبدل بالخطأ.

## 9. ملاحظات أمنية مهمة قبل الإطلاق

- غيّر `NEXTAUTH_SECRET` وكل القيم في `.env.example` قبل الإنتاج — لا تستخدم القيم الافتراضية.
- فعّل 2FA لحساب المدير فور أول تسجيل دخول.
- راجع `Content-Security-Policy` في `next.config.js` وحدّثها إذا أضفت نطاقات خارجية (خطوط، تحليلات، إلخ).
- تأكد أن `/admin` و`/api` مستثناة من الفهرسة (مُطبّق مسبقاً في `robots.ts`).
- هذا الموقع إعلامي فقط عمداً: لا توجد فيه أي مسارات لتسجيل مستخدمين عامين أو استقبال طلبات/مدفوعات — حافظ على هذا الفصل عند أي تطوير مستقبلي.

## 10. تحسينات التحديث الأخير (تجربة المستخدم، الأداء، الأمان)

تمت إضافة هذه التحسينات مع الحفاظ الكامل على الهوية البصرية (الأزرق `#0072BC`، الكحلي، الأبيض، الأصفر، الأحمر للعاجل فقط، Cairo/Tajawal) والبنية والمحتوى الحاليين:

**تجربة المستخدم:**
- Skeleton Loading عبر ملفات `loading.tsx` لكل مسار رئيسي (بدل شاشة فارغة أثناء التحميل).
- صفحات `error.tsx` و`global-error.tsx` و`not-found.tsx` مخصّصة بنفس الهوية بدل شاشات Next.js الافتراضية.
- نظام Toast Notifications (`components/Toast.tsx`) للنجاح/الخطأ في كل عمليات لوحة التحكم.
- `ConfirmDialog` بدل `confirm()` المتصفح — Modal فعلي مع دعم Escape والتركيز التلقائي.
- تحذير "تغييرات غير محفوظة" (`beforeunload`) في نماذج الأخبار والبيانات الصحفية.
- تبديل "مميز" فوري (Optimistic UI) من قائمة الأخبار مباشرة دون فتح نموذج التعديل.
- بحث فوري مع اقتراحات أثناء الكتابة (`SearchBox` + `/api/search/suggest`)، Debounce 300ms + إلغاء الطلبات القديمة تلقائياً.
- "تحميل المزيد" (`LoadMoreNews` + `/api/public/news`) بدل إعادة تحميل الصفحة عند التصفح.
- قائمة جوال (`MobileMenu`) بإغلاق تلقائي بـ Escape ومنع تمرير الخلفية.
- انتقال ناعم بين الصفحات عبر `template.tsx` (مع احترام `prefers-reduced-motion`).

**الأداء:**
- Server Components للجلب الأولي، مع API خفيفة فقط للتفاعلات (تحميل المزيد، الاقتراحات، التبديل الفوري).
- ISR (`revalidate = 60`) على الصفحة الرئيسية.
- بنية أساسية PWA: `manifest.json` + Service Worker بسيط لصفحة عدم الاتصال فقط (لا يخزّن محتوى إخبارياً حتى لا يُعرض محتوى قديم) — **يلزم إضافة أيقونات فعلية في `public/icons/icon-192.png` و`icon-512.png` قبل الإنتاج**، فهي غير مُضمَّنة هنا.

**لوحة التحكم:**
- رسم بياني (`ActivityChart` عبر recharts) لنشاط النشر آخر 14 يوماً في `/admin/dashboard`.
- بطاقة "آخر العمليات" من سجل التدقيق مباشرة في لوحة التحكم (تظهر فقط لمن يملك `audit_log.view`).
- صفحة `/admin/settings` لتفعيل/تعطيل المصادقة الثنائية (2FA) بالكامل: توليد سرّ، عرض QR، تأكيد بالرمز.
- **نظام أدوار وصلاحيات (RBAC) حقيقي بالكامل**: أربعة أدوار افتراضية (مدير عام/مدير محتوى/محرر/مُطّلع)
  قابلة للتوسعة، صفحتا `/admin/users` و`/admin/roles` لإدارتها، وتطبيق الصلاحيات فعلياً في كل صفحة
  إدارة وكل API route (وليس بإخفاء الأزرار فقط) — التفاصيل الكاملة في القسم 4 أعلاه.

**الأمان:**
- تدفّق تفعيل 2FA الفعلي (`/api/admin/2fa/setup|enable|disable`) بدل الاكتفاء بالحقول في قاعدة البيانات دون واجهة.
- توحيد كل ألوان الحالات الحرجة/الأخطاء على لون `urgent` الأحمر المعتمد بدل ألوان حمراء عشوائية خارج الهوية.
- حماية من رفع الصلاحيات (Privilege Escalation)، وقفل عرضي للنظام (تعطيل/حذف حساب النفس، أو آخر مدير عام)، وسجل تدقيق كامل لعمليات المستخدمين والأدوار (راجع القسم 4).

**ما لم يُنفَّذ بالكامل عمداً (خارج نطاق هذه الدفعة، وموثّق هنا صراحة بدل الادّعاء بإنجازه):**
- تعدد اللغات (i18n) الكامل بمسارات `[locale]`: لم يُطبَّق لأنه يتطلب إعادة هيكلة كل مسارات `src/app` دفعة واحدة، وهو تغيير كبير قد يكسر الروابط الحالية دون تنسيق مسبق. البنية الحالية (رموز الألوان، النصوص، المكوّنات) جاهزة لذلك لاحقاً كخطوة منفصلة.
- تكامل خدمة مراقبة أخطاء/أداء خارجية (مثل Sentry): `error.tsx`/`global-error.tsx` يسجّلان الآن عبر `console.error` فقط؛ ربطها بخدمة فعلية يتطلب مفتاح API خاص بالمشروع.
- **نموذج بيانات للإعلانات (Ads)**: لا يوجد جدول مخصّص للإعلانات تحديداً — يحتاج إضافة جدول جديد إن لزم مستقبلاً. (كل ما عدا ذلك من "الصفحات المؤسسية" كامل الآن — انظر أدناه.)
- **قابلية توسّع لوحة التحليلات لحركة زيارات كبيرة جداً**: `getPageViewsSeries()` في `/admin/dashboard` يجلب كل صفوف `page_views` لآخر 14 يوماً ثم يجمّعها في الكود (نفس أسلوب رسم نشاط النشر القديم)؛ مناسب لحجم موقع إعلامي حكومي عادي، لكنه يحتاج لاحقاً الانتقال إلى تجميع مسبق (Materialized View أو مهمة مجدولة) إن ارتفعت الزيارات بشكل كبير جداً.

**أُنجز بالكامل في هذه الدفعة (كان موثّقاً أعلاه كناقص، وأصبح الآن مكتملاً):**
- **CRUD كامل للفعاليات/البرامج/التقارير والمعرض الإعلامي من لوحة التحكم**: `/admin/events`, `/admin/programs`, `/admin/reports` تملك نماذج إضافة/تعديل وAPI كاملة؛ `/admin/media-center` (بقسمَي معارض الصور `/admin/media-center/galleries` والفيديوهات `/admin/media-center/videos`) مكتمل أيضاً بصلاحيات `media_center.*` خاصة به.
- **مكتبة وسائط دائمة**: `/admin/media` يعرض كل الملفات المرفوعة سابقاً (لا الجلسة الحالية فقط) عبر `GET /api/media`، مع بحث وحذف (`DELETE /api/media/[id]`) يمنع حذف ملف لا يزال مستخدَماً في محتوى آخر.
- **صفحات ثابتة وقيادات وقوائم**: `/admin/pages` (تُعرض عاماً على `/pages/[slug]`)، `/admin/leadership` (تُعرض على `/leadership` و`/about`)، و`/admin/menus` (روابط إضافية تظهر تلقائياً في رأس/تذييل الموقع العام عبر `Header`/`Footer` دون تعديل كود) — كل منها بصلاحيات RBAC مستقلة (`pages.*`, `leadership.*`, `menus.*`).
- **إعدادات تواصل عامة قابلة للتعديل**: بريد/هاتف/عنوان المفوضية وروابط التواصل الاجتماعي المعروضة في `/contact` والتذييل، تُدار الآن من `/admin/settings` (قسم مخصّص يظهر فقط لمن يملك `settings.manage`) بدل التعديل المباشر في قاعدة البيانات. **مع ملاحظة تصميمية مهمة:** لم يُبنَ نموذج تواصل عام (Contact Form) يستقبل رسائل من الجمهور، لأن هذا يخالف الطبيعة المتعمَّدة للموقع كموقع إعلامي بحت (انظر القسم 9) — التواصل الفعلي يبقى عبر البريد/الهاتف الموضَّحين فقط.
- **لوحة تحكم تحليلية حقيقية**: جدول `page_views` جديد يسجّل زيارات الجمهور الفعلية (بلا أي بيانات شخصية — لا IP، لا معرّف جهاز) عبر `AnalyticsTracker` (مكوّن عميل خفيف يرسل `sendBeacon`) و`POST /api/public/pageview` (نقطة عامة محمية بمعدّل طلبات + تحقّق صارم من شكل المسار). `/admin/dashboard` يعرض الآن: زيارات 24 ساعة/7 أيام/30 يوماً، رسماً بيانياً يومياً حقيقياً، أكثر الأقسام والصفحات زيارة، وأكثر الأخبار قراءة — منفصلة تماماً عن إحصاءات نشر المحتوى (`ActivityChart`) التي كانت موجودة سابقاً.
- **إصلاح جانبي**: هيدر/فوتر/شريط العاجل للموقع العام كانا يُعرضان (خطأً) فوق كل صفحات `/admin` بما فيها تسجيل الدخول؛ أُضيف `SiteChrome.tsx` لإخفائهما في أي مسار يبدأ بـ `/admin`.
